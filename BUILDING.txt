Building the RimWorld 1.6 / 1.7 update

Install a .NET 10 SDK, RimWorld 1.7 and the Harmony workshop mod.
From this directory:

  dotnet build Source/ArchotechEye_InvisibilityDetection.csproj -c Release

The DLL is written to 1.7/Assemblies/. Game and Harmony references are not
copied into the mod. Override non-default installation paths with:

  -p:RimWorldDir="C:\path\to\RimWorld"
  -p:HarmonyPath="C:\path\to\0Harmony.dll"

Build automated checks with:

  dotnet build Tests/ArchotechEye.Tests.csproj -c Release

Run against the installed game's Waylith runtime with a .NET 10 host:

  dotnet exec --runtimeconfig "GAME\RimWorld.runtimeconfig.json" --depsfile "GAME\RimWorld.deps.json" Tests/bin/Release/net10.0/ArchotechEye.Tests.dll "GAME" "HARMONY_ASSEMBLIES_DIRECTORY"

Replace GAME and HARMONY_ASSEMBLIES_DIRECTORY with actual directories.
The harness loads the real assemblies but does not start a game or modify
save files. Its minimal map/pawn fixtures do not exercise the graphics UI.

The root Assemblies/ DLL is the 1.6 build. To rebuild it:

  dotnet build Source/ArchotechEye_InvisibilityDetection.csproj -c Release -p:RimWorldVersion=1.6

If a local 1.6 installation is unavailable, the project automatically uses
Krafs.Rimworld.Ref 1.6.4871 (compile-time references only). It does not ship
game assemblies with the mod. See https://www.nuget.org/packages/Krafs.Rimworld.Ref/1.6.4871
Use -p:UseRimWorldReferencePackage=false to require local game references.
The 1.7 API cannot be used as a reference for a 1.6 build.

Ratkin Anomaly integration checks run automatically when workshop item
3716441120 is installed. To use another copy, supply its mod root as the
third argument to the test harness, after GAME and HARMONY_ASSEMBLIES_DIRECTORY.
An optional fourth argument selects a specific mod DLL for compatibility
testing under the 1.7 runtime (including the .NET Framework 1.6 build).
The tests load its real De_lovely and Obsession classes and check their
vanilla invisibility comps. Ratkin Anomaly is never a required dependency
of the production assembly. Its hide-and-seek discovery events are not
triggered by revealing a silhouette.

Developer-only compatibility diagnostics (1.1.0-beta.3):
  1. Enable Development mode in RimWorld's options.
  2. Open the developer Debug actions menu and search for:
       Inspect invisibility compatibility
     Category: Archotech Eye.
  3. Click the pawn's cell. The native debug pawn tool also finds invisible
     pawns in that cell; it does not reveal the rest of the map. Multiple
     pawns in one cell can open multiple reports. Right-click to exit the tool.
  4. Read the report, or use Write Report to Log to retain it in Player.log.

Reports are localized in English and Korean. They identify the target by
numeric pawn ID, DefName, class/assembly and source mod/package ID. All
hediff component and ThingComp types are listed without guessing stealth
from their names or executing arbitrary custom stealth properties.
The report includes Harmony owners on the game's two visibility predicates.

The game predicates are read with this mod's reveal override suppressed,
not with all Harmony patches removed. Show Hidden Pawns and player-faction
visibility still affect the hidden-from-player predicate. A false game
predicate without a native invisibility component means inconclusive:
the pawn may simply be visible, or may use an unrelated custom system.

Observers' cached detection and the cache refresh tick are shown separately
from current distance/line of sight. Line of sight is only measured by the
explicit debug action and is skipped outside 36 tiles. Nothing updates the
cache, changes a hediff, or calls a discovery event. No diagnostic code is
added to a tick or render loop. The tool inspects Pawns, not arbitrary
hidden buildings, items, implanted entities, or unknown custom stealth APIs.

The 116 automated checks include real Ratkin Anomaly classes, external
Harmony visibility patches, broken component data, nulls, cache preservation,
observer isolation, and English/Korean key coverage. The 1.6 DLL is also run
under the 1.7 harness, which is not a real 1.6 runtime or a UI playtest.

Publishing policy: Steam uploads are manual and handled by the user.
Development/build/test/package requests must not trigger a Steam upload.

Optional Alpha Animals stalking support (1.1.0-beta.4):
  - Alpha Animals is not required and no external mod DLL is redistributed.
  - The native invisibility predicate remains unchanged. The separate
    adapter recognizes the actual Hediff_Stalking state type and adds it
    to the same 36-tile/LoS cache, using no race or DefName detection rules.
  - The graphics patch only changes the local hidden-graphics branch when
    a player-controlled colonist's eye has a cached detection. It preserves
    the actual hediff, original AI rules, and ordinary/alternate graphics.
  - Rendering reads only the cache. It does not check LoS, scan hediffs,
    reflect over mods, remove camouflage or invoke discovery events.
  - Mod settings: Alpha Animals stalking camouflage detection. Enabled
    by default for supported Alpha Animals versions, and can be disabled
    without disabling native invisibility detection. Cache latency is up
    to 60 game ticks. Unsupported graphics API shapes disable the adapter.
  - The developer report shows adapter availability, the active option,
    and whether the actual stalking hediff exists. It does not guess other
    custom stealth systems from their names.

The runtime harness preloads the installed 1.7 Alpha Animals DLL by default
when present. A fifth argument selects another version directory (the one
containing Assemblies/), such as WORKSHOP/1541721856/1.6. Use '-' as the fifth
argument for a fresh-process test without loading Alpha Animals. The fourth
argument remains the mod DLL to test. No direct Alpha Animals compile-time
reference is used in production or tests.

The matrix passed 160 assertions with the real Alpha Animals DLL and 120
without it. It covers native-only reproduction, missing dependencies,
settings toggles, walls, 36/37-tile boundaries, per-observer isolation,
non-player observers, render-parameter alpha/material flags, stale caches,
overlapping native/custom invisibility, graphics invalidation, and map
removal. Graphics invalidation is intercepted in the headless harness;
the textures, in-game settings window and final rendered silhouette have
not been visually tested. All runtime checks use the installed 1.7 engine
assemblies, even when the mod or Alpha Animals DLL under test is for 1.6.

Silhouette readability settings (1.1.0-beta.5):
  - Open this mod's normal settings window; Development mode is not needed.
  - Opacity: 15%-80%. Higher values are more visible, but remain translucent.
  - Color: original, cyan, gold or white. Colored modes blend their tint
    with the incoming draw tint and still use the original pawn textures.
  - Improve visibility applies 60% opacity and cyan. Restore appearance
    defaults applies 30% and original colors, without changing stalking
    compatibility. Existing config files retain those original defaults.
  - World-draw parameters read these values directly, using only already
    published detection caches. No extra LoS, hediff scan, material, draw
    call or graphics invalidation is needed when changing appearance.
  - Portraits, cached atlas passes and undetected targets stay unchanged.
    Combat, the 36-tile radius and 60-game-tick cache stay unchanged too.
  - The native Scribe save/load path is tested with every palette, older
    settings and invalid values, using temporary files only. Tests never
    read or write the player's real configuration files.
  - The latest matrix passed 229 checks with Alpha Animals and 188 without
    it for each mod DLL under the 1.7 runtime. The real 1.6 engine, settings
    UI layout and final texture/shader appearance remain unverified.

Runtime load folders:
  1.6: root (updated .NET Framework DLL), Common (translations)
  1.7: Common (translations), 1.7 (new DLL)
